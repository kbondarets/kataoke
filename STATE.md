## Последняя задача

**Трек не распознавался: медиа-элемент вне DOM.** Логи с живой страницы показали
`медиаЭлементов: 0` и `mediaSession: null` при играющем треке — плеер держит
`<audio>` вне документа, поэтому из изолированного мира его не видно. Ветка
`fix/yandex-page-agent`.

Решение: агент в MAIN-мире страницы (`src/adapters/yandex-music/page-agent.ts`):

- перехватывает `HTMLMediaElement.prototype.play` — единственное событие, через
  которое проходит любой плеер, даже с элементом вне DOM;
- читает `navigator.mediaSession.metadata` с правами страницы (там он заполнен);
- раз в 250 мс отправляет снимок через `window.postMessage`.

Адаптер (`yandex-adapter.ts`) слушает сообщения, валидирует их и отдаёт ядру
через прежний интерфейс `PlayerAdapter` — ядро и UI не изменились. Метаданные
приоритетнее позиции: текст покажется, даже если элемент ещё не перехвачен.

Ранее в этой же задаче исправлено (коммиты `ad0a03e`, `9d03176`): `duration:
Infinity` у MSE ломала распознавание, `idle` рендерил `null`, слушатели не
перевязывались при пересоздании элемента, провайдер не умел искать без
длительности, `content.js` собирался как ES-модуль, а запрос к LRCLIB шёл из
content script в обход CORS.

Добавлена диагностика: `[kataoke:agent] запущен в мире страницы`,
`[kataoke] агент страницы на связи` (со снимком состояния), `[kataoke] трек`,
`[kataoke] трек не распознан`.

Проверено: `npm run check` — typecheck ✓, 85/85 тестов ✓ (было 69, +16), build ✓.
Не проверено: поведение в живом Яндекс Музыке после правок — проверяет владелец.

## Подводные камни

- **«Дорогой сервер» — миф из-за тарифа за простой.** Alignment нужен урывками и
  один раз на трек; с кешем и офлайн-обработкой расходы на старте — единицы
  долларов или ноль. См. `VISION.md` §9.1.
- **Яндекс Музыка не имеет стабильного публичного API.** Метаданные трека
  придётся брать из DOM/`mediaSession`/`document.title`. При редизайне адаптер
  ломается — это ожидаемо, чинится в одном файле.
- **`currentTime` обновляется рывками** — без интерполяции подсветка дёргается.
  См. `skills/media-sync`.
- **LRCLIB «не находит» чаще из-за матчинга, чем из-за отсутствия текста.**
  Нормализация `feat.`/`remaster`/длительности — обязательная часть провайдера.
- **Content script в MV3 — классический скрипт, не модуль.** Если сборка вынесет
  общий код в `chunks/`, файл начнётся с `import` и расширение молча не запустится.
  Поэтому `content` и `background` собираются **двумя отдельными прогонами**
  (`vite build --mode content` / `--mode background`), а сборка падает, если в
  `content.js` появится `import`/`export`.
- **Запросы к провайдеру — только из service worker.** `host_permissions` снимает
  CORS лишь для него; `fetch` из content script подчиняется политике страницы.
  Content script общается с фоном сообщениями (`src/providers/background-bridge.ts`).
- **`sendMessage` требует `return true` в слушателе** для асинхронного ответа:
  без него канал закрывается сразу и приходит `undefined`.
- **Медиа-элемент Яндекс Музыки живёт вне DOM.** Плеер создаёт `<audio>` через
  `new Audio()` и не вставляет в документ, поэтому из изолированного мира
  расширения `querySelectorAll('audio, video')` даёт **0**, а `mediaSession`
  пуст. Именно поэтому оверлей долго оставался пустым. Решение — агент в
  MAIN-мире страницы (`src/adapters/yandex-music/page-agent.ts`), который
  перехватывает `HTMLMediaElement.prototype.play` и читает `mediaSession` с
  правами страницы. Общение — только через `window.postMessage`: у MAIN-мира нет
  `chrome.runtime`, у изолированного нет доступа к объектам страницы.
- **`world: "MAIN"` в манифесте** требует отдельного файла в `content_scripts`
  и `run_at: document_start` — иначе `play()` будет перехвачен уже после того,
  как плеер его вызвал.
- **`media.duration` у MSE-плеера бывает `Infinity`.** Если адаптер требует
  конечную длительность, трек не распознаётся вообще и расширение молчит.
  «Неизвестно» должно быть валидным состоянием (`0`), а не поводом вернуть `null`.
- **Медиа-элемент появляется и пересоздаётся.** Content script стартует раньше
  плеера, а SPA-навигация меняет `<audio>`. Слушатели, навешенные один раз,
  тихо перестают работать — нужен периодический переподхват.
- **Ошибки в консоли музыкального сервиса — не наши.** `log.strm.yandex.ru`
  и `mc.yandex.ru` блокирует адблокер, к расширению это отношения не имеет.
  Признак наших проблем — сообщения с префиксом `[kataoke]`.
- **MV3 service worker выгружается** — никакого состояния в памяти.
- **DRM-сервисы не отдают аудиопоток расширению** — любые идеи про стемы и
  приглушение вокала на них нереализуемы.
