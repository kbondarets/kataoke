# Скилл: расширение Manifest V3

## Когда нужен

- Правка `manifest.json`.
- Работа с `background` (service worker) и `content`.
- Проблемы «не запускается», «не видит страницу», «запрос заблокирован».
- Публикация и ревью в Chrome Web Store.

## Минимальный manifest (ориентир)

```json
{
  "manifest_version": 3,
  "name": "kataoke",
  "version": "0.0.1",
  "description": "Караоке-тексты поверх любого музыкального сервиса",
  "action": { "default_popup": "popup.html" },
  "content_scripts": [
    {
      "matches": ["https://music.yandex.ru/*", "https://www.youtube.com/*"],
      "js": ["content.js"],
      "run_at": "document_idle"
    }
  ],
  "host_permissions": ["https://lrclib.net/*"],
  "permissions": ["storage"],
  "background": { "service_worker": "background.js", "type": "module" }
}
```

Правила:

- `content_scripts.matches` — **только** поддерживаемые домены. Не `<all_urls>`.
- `host_permissions` — только домены провайдеров.
- `permissions` — минимум; каждое новое надо обосновать на ревью.
- Никаких `tabs`, `webRequest` на старте, если не нужны.

## Content script

- Изолированный мир: DOM страницы доступен, но JS-переменные страницы — нет.
- Монтируется в страницу, но не в `document.head` и не в `document.body` — в
  `document.documentElement`, чтобы избежать SPA-перерисовок.
- Работает в ограниченном окружении: CSP страницы не влияет на скрипт расширения,
  но влияет на вставку сторонних ресурсов.
- Нужны точные имена: от `window` страницы — `window.wrappedJSObject` только в
  Firefox при необходимости; в Chrome — нет.
- Не пытаться читать защищённые DRM-данные. Доступа к PCM нет.
- **Content script — классический скрипт, не ES-модуль.** Сборка не должна
  выносить общий код в чанки: файл с `import` не загрузится, и это видно только
  по отсутствию любых логов. Content и background собираются отдельными прогонами.
- События медиа-элемента навешиваются заново, если элемент пересоздан (SPA),
  иначе подписки тихо перестают работать.

## Service worker (MV3) и его ограничения

- Не живёт постоянно: просыпается по событию, может быть выгружен через ~30 сек
  простоя.
- Значит, **никакого состояния в памяти**. Состояние — только `chrome.storage`.
- `setInterval`/`setTimeout` надежно не работают; для периодических задач —
  `chrome.alarms`.
- Сетевые запросы к сторонним доменам — **только из service worker**.
  `host_permissions` снимает CORS лишь там; `fetch` из content script
  подчиняется политике страницы и может быть заблокирован. Content script
  просит фон через `chrome.runtime.sendMessage`.

## Messaging

- Никаких «globals» между контекстами. Только `chrome.runtime.sendMessage` /
  `chrome.tabs.sendMessage`.
- Все сообщения — проверяемый тип. Невалидное — игнор + лог.
- Ответ может не прийти (страница закрылась) — обработка таймаута обязательна.

## CSP

- MV3 не разрешает удалённый код. Только то, что в бандле.
- Никаких `eval`, `new Function`, `innerHTML` для шаблонов из данных.
- Весь JS — в файлах расширения.

## Сеть и приватность

- Ключей в бандле нет. Внешние источники MVP — без ключей.
- Не отправлять на серверы ничего, что не нужно (никакой телеметрии прослушивания
  в MVP).
- Не собирать в логах названия треков с привязкой к личности.

## Отладка

- `chrome://extensions` → режим разработчика → «Загрузить распакованное» → папка
  `dist/`.
- После правки `manifest.json` — перезагрузка расширения обязательна.
- Консоль content script — в DevTools страницы, вкладка «Контексты».
- Консоль service worker — ссылка в карточке расширения.
- `chrome.storage` — через консоль расширения (асинхронный API).

## Совместимость с Firefox

- Firefox поддерживает MV3, но с отличиями (`background.scripts` vs
  `service_worker`, некоторые API).
- В MVP — держать совместимость в уме, но таргетировать Chrome/Edge, а Firefox
  добавить отдельной задачей.
- Не использовать Chrome-специфичные `chrome.*` вызовы без обёртки; по возможности
  `browser` — polyfill.

## Ревью и публикация

- Расширение, которое читает страницы музыкальных сервисов, проверяется
  модерацией особенно придирчиво (права на чтение DOM).
- Готовьте объяснение разрешений для каждого домена.
- Никаких «серых» практик: перехват трафика, инъекция в сторонние сайты, обход
  рекламы.

## Красные флаги

- `<all_urls>` в `matches`/`host_permissions`.
- `eval`, `new Function`.
- Состояние в переменных service worker, которое «должно жить».
- Сеть из popup, минуя общий модуль клиента.
- Установка глобальных стилей в `document.head` (ломает сайт).
