# Скилл: провайдер текстов

## Когда нужен

- Работа с LRCLIB (основной источник MVP).
- Добавление нового клиентского источника.
- «Текст не находится», «находится не тот текст», «ошибка в консоли».

## LRCLIB: что это и как с ним жить

- Открытый API (`https://lrclib.net/api`), без ключа.
- Основные методы:
  - `GET /api/get?artist_name=&track_name=&album_name=&duration=` — точный поиск;
  - `GET /api/search?q=` или `?track_name=&artist_name=` — поиск-список;
  - `GET /api/get/{id}` — по id.
- Ответ содержит `syncedLyrics` (LRC с таймингами, может быть `null`),
  `plainLyrics`, а также `duration`, `instrumental` (флаг инструментала).
- Уважение к сервису: идентифицируйте приложение в `User-Agent`, не устраивайте
  пачку параллельных запросов, кешируйте локально.
- Флаг `instrumental: true` — отдельное состояние: показываем «Это инструментал,
  текста нет», а не пустой экран.

Точные пути и параметры сверяйте с актуальной документацией LRCLIB — API
эволюционирует; в коде держать их в одном месте (константы).

## Матчинг трека (основной источник «не находит»)

Матчинг — главная причина, что «текст есть, но не нашёлся». Нормализовать обе
стороны:

- `feat.` / `ft.` / `featuring`, `prod.`, `(Remastered 2011)`, `[Radio Edit]`,
  `(Live)`, `- Single Version`, `(feat. X)`;
- регистр, лишние пробелы, ё/е, `&` vs `and`, `,` vs `·`;
- вариации артиста: `Кино` / `Kino`, `X feat. Y` vs `X, Y`;
- дублирующиеся суффиксы каталога (`(Deluxe Edition)`);
- латиница/кириллица в названии — перекрёстная транслитерация повышает попадаемость,
  но **без фанатизма**: ложные совпадения хуже.

Проверять **длительность**: разница больше 5–7 секунд — вероятно другой трек
(ремикс, live, extended edit). Отбрасывать или давать ниже приоритет.

Что отдавать провайдеру:

| Поле | Обязательность | Комментарий |
|---|---|---|
| `artist` | да | первый исполнитель / основной |
| `title` | да | без суффикса (feat.) |
| `album` | желательно | поднимает точность |
| `durationSec` | да | ключ к кешу и к отсеву |

## Контракт провайдера

```ts
interface LyricsProvider {
  id: string;
  lookup(track: TrackInfo, signal: AbortSignal): Promise<LyricsResult | null>;
}
```

- `signal` — обязательный, для отмены при смене трека и таймаута.
- `null` — «текста нет», это **не ошибка**.
- Ошибка — отдельный результат/исключение, которое UI покажет как «не удалось
  получить» с возможностью повторить.

## Сетевые правила (жёсткие)

- **Таймаут** — 5–10 секунд. Реализация через `AbortSignal.timeout()` или
  `AbortController`.
- При смене трека старый запрос — `abort()`.
- Не ретраить бесконечно: 1 повтор на сетевой сбой, не на 404.
- Валидация ответа: `unknown` → проверка формы → типизированный объект.
  Приводить через `as` запрещено.
- Не логировать ответы целиком (это могут быть тексты песен, а также лишний шум).

## Кеш

- Ключ: `providerId + normalizedArtist + normalizedTitle + roundedDuration`.
  Округление длительности до секунды!
- Значение: `LyricsResult | null` (помним и «нет текста», чтобы не спрашивать снова).
- Хранилище: `chrome.storage.local`.
- TTL: для отрицательных результатов — короче (например, 7 дней), для
  положительных — практически бессрочно, но с версией схемы для инвалидации при
  изменении парсера.
- Лимит размера: тексты большие; хранить не тысячи треков, а сотни, с вытеснением
  по давности.

## Ошибки: что увидит пользователь

| Ситуация | Текст |
|---|---|
| Нет соединения / таймаут | «Не удалось получить текст. Проверьте соединение.» |
| Сервис ответил ошибкой | «Сервис текстов временно недоступен. Попробуйте позже.» |
| Текст не найден | «Текст для этого трека не найден.» |
| Инструментал | «Это инструментальная композиция — текста нет.» |
| Пришёл plain без таймингов | (показываем текст, без караоке) |

Все — по-русски, без кодов и стектрейсов.

## Уважение к источникам

- Не снимать ограничения и не обходить блокировки.
- Не скрапить сервисы, где это прямо запрещено.
- Для коммерциализации потребуется лицензия (`VISION.md` §10) — клиентский
  скрапинг не является решением.

## Красные флаги

- Запрос без `AbortSignal`.
- `res.json() as SomeType` без проверки.
- Параллельный опрос одного трека (два запроса на один трек из-за дубля событий).
- Отсутствие кеша.
- Текст ошибки на английском или с кодом ответа.
