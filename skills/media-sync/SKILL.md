# Скилл: синхронизация с медиа-элементом

## Когда нужен

- Реализация `PlayerAdapter.getPositionSec()`.
- Любая отладка «строка отстаёт / убегает / дёргается».
- Обработка перемотки, паузы, смены скорости воспроизведения.

## Что читать в проекте

- `projectRules.md` §6 (sync engine).
- `VISION.md` §4.3.
- `.clinerules/workflows/review.md` шаг 3 (что проверяет ревьювер).

## Главный принцип

**Позиция — из медиа-элемента.** Источник истины — `<video>` или `<audio>` на
странице: `element.currentTime`, `element.paused`, `element.playbackRate`,
`element.duration`. DOM-прогресс-бар показывает то, что сервис решил показать, и
это не истина во времени.

## Интерполяция (обязательна)

`currentTime` в браузере обновляется не на каждый кадр (часто раз в 200–250 мс, а
на некоторых сервисах — грубее). Если читать его в `requestAnimationFrame`
напрямую, подсветка дёргается.

Правильный подход — хранить последний **сэмпл** и интерполировать:

```ts
type Sample = { mediaTimeSec: number; wallMs: number; rate: number; playing: boolean };

function positionAt(sample: Sample | null, nowMs: number): number {
  if (!sample) return 0;
  if (!sample.playing) return sample.mediaTimeSec;
  const elapsedSec = (nowMs - sample.wallMs) / 1000;
  return sample.mediaTimeSec + elapsedSec * sample.rate;
}
```

Сэмпл обновлять при событиях плеера и периодически (например, раз в 250–500 мс),
но **позицию считать от `performance.now()`**, а не от последнего опроса.

### Почему не `Date.now()`
`Date.now()` может прыгнуть при смене системного времени/NTP. `performance.now()`
монотонен.

### Ограничитель дрейфа
Если интерполяция ушла от свежего `currentTime` больше чем на N мс (например,
120–250 мс), это признак перемотки/буферизации — сбросить сэмпл на свежее
значение, а не «догонять» плавно.

## События, которые обязаны быть обработаны

| Событие | Что делаем |
|---|---|
| `play` | сэмпл: `playing=true`, `wallMs=now` |
| `pause` | сэмпл: `playing=false`, фиксируем `mediaTimeSec` |
| `seeking` / `seeked` | пересоздать сэмпл; на `seeked` — сбросить «залипание» |
| `ratechange` | обновить `rate` в сэмпле, не пересчитывая прошлое |
| `ended` | `playing=false`, конец таймлайна |
| `loadedmetadata` / `durationchange` | перечитать `duration` |
| `waiting` / `stalled` / `playing` (буферизация) | пауза интерполяции на `waiting`, возобновление на `playing` |
| смена трека | полностью сбросить сэмпл и таймлайн |

Список событий браузера неполный: некоторые SPA-плееры не кидают `ratechange`,
поэтому периодический опрос `playbackRate` раз в секунду — нормальная
предосторожность.

## Смена трека (SPA)

- Музыкальные сервисы — SPA. Трек меняется без перезагрузки.
- Слушать `loadstart`/`loadedmetadata` на медиа-элементе и/или `MutationObserver`
  на контейнере трека.
- Перехват навигации: `history.pushState` / `history.replaceState` и `popstate`.
- При смене трека: новый `trackId` → сброс таймлайна, перезапрос текста (с кешем),
  сброс индекса активной строки.

## Смещение и опережение

- Пользователь читает заранее: подсветка должна слегка **опережать** звук
  (обычно +80…150 мс). Смещение — настройка, но с разумным дефолтом.
- Смещение добавлять **в момент поиска активной строки**, не в таймлайн: иначе при
  перемотке оно может примениться дважды.
- Это смещение — **не** заменяет `[offset]` из LRC. Это два независимых числа:
  `[offset]` — свойство файла, опережение — предпочтение показа.

## Дешёвый рендер

- `requestAnimationFrame` — цикл, но состояние меняется редко.
- Вычислять активную строку/слово; если изменилась — обновлять (setState), иначе
  ничего не делать.
- Не обновлять React-состояние каждый кадр — это главная причина лагов и
  энергопотребления.
- Для караоке-плавности по словам можно анимировать CSS-переменную прогресса слова
  напрямую (`style.setProperty`), не дёргая компонент.

## Как проверять без браузера

Sync engine должен быть чистым модулем:

```ts
engine.setTimeline(timeline);
engine.updateSample({ mediaTimeSec: 12.3, wallMs: 0, rate: 1, playing: true });
expect(engine.activeLineAt(0, /* nowMs */ 0)).toBe(0);
expect(engine.activeLineAt(0, 1000)).toBe(1); // если строка 1 начинается на 12.34+1
```

Проверки-минимум:

- позиция растёт с `rate=1` и `rate=0.75`;
- при `playing=false` позиция не растёт;
- при `seek` позиция мгновенно прыгает;
- при дрейфе сверх порога сэмпл сбрасывается.

## Красные флаги

- Чтение `element.currentTime` без интерполяции и без события `timeupdate` —
  дёргается.
- `setInterval(…, 16)` вместо `requestAnimationFrame`.
- Обновление состояния React на каждом кадре.
- Позиция из DOM-элемента с прогрессом (полоска, `aria-valuenow` плеера).
- Отсутствие обработки `seek`: пользователь перемотал — текст остался на старом
  месте.
