# Скилл: оверлей в Shadow DOM

## Когда нужен

- Создание/переделка UI оверлея.
- «Наш стиль перебивает сайт», «сайт перебивает наш стиль», «оверлей уехал».
- Оверлей не перерисовывается после смены трека или навигации.

## Что читать в проекте

- `projectRules.md` §7.
- `VISION.md` §4.4.

## Базовая схема монтирования

```ts
const host = document.createElement('div');
host.id = 'kataoke-root';
const shadow = host.attachShadow({ mode: 'open' });
document.documentElement.appendChild(host);

const style = new CSSStyleSheet(); // или <style> с текстом из бандла
shadow.adoptedStyleSheets = [style];
render(<Overlay />, shadow as unknown as Element);
```

- `mode: 'open'` — чтобы можно было отлаживать; закрытый root не даёт выигрыша в
  безопасности для расширения.
- Монтировать в **один** контейнер на странице (проверять, нет ли уже нашего
  `#kataoke-root` — при повторной инъекции content script бывает дубль).

## Изоляция стилей

- Внутри shadow root стили сайта **не применяются** к нашему UI — это и есть цель.
- Наследуемые свойства (`color`, `font-family`, `font-size`, `line-height`,
  `direction`) **протекают** внутрь. Обязательно задавать их явно на корневом
  элементе оверлея.
- Наш CSS наружу не протекает, **пока** нет `:host-context`, `::part` и подобных
  выходов. Не использовать.
- Не полагаться на глобальные CSS-переменные страницы — задавать собственные с
  префиксом (`--kataoke-*`).
- Шрифт: использовать системный или встроенный (учтите требования CSP у page
  не действуют внутри shadow root для встроенных стилей, но **внешние** шрифты
  через `@font-face` с URL — отдельная история, проверяйте).

## Позиционирование

- Хост — `position: fixed; inset: 0; pointer-events: none;` чтобы не блокировать
  клики по сайту.
- Внутренние интерактивные элементы (кнопки, панель) — `pointer-events: auto`.
- Позиция относительно медиа-элемента: `getBoundingClientRect()` + пересчёт на
  `ResizeObserver` (медиа-элемент) и `IntersectionObserver` (если скрыли плеер).
- Пересчёт: `resize`, `scroll` (с `passive: true`), изменение layout сайта.
- Безопасные зоны: не перекрывать кнопки play/pause, полосу прогресса и громкость.
  Дефолт — снизу или над плеером, с отступом.

### z-index

- Порядок наложения задаётся родительским контекстом. `position: fixed` на корне
  страницы с огромным `z-index` (например, `2147483000`) — обычная практика.
- Не полагаться на «наверняка хватит»: проверять на целевых сервисах вручную.
- Если сайт использует `transform` на предке — `fixed` ведёт себя как `absolute`;
  поэтому монтировать в `document.documentElement`, а не в случайный контейнер.

## SPA-навигация

- Трек меняется без перезагрузки. Оверлей не должен размонтироваться.
- Перехват:
  ```ts
  const wrap = (fn: History['pushState']) => function (this: History, ...args) {
    const r = fn.apply(this, args);
    window.dispatchEvent(new Event('kataoke:navigation'));
    return r;
  };
  history.pushState = wrap(history.pushState);
  ```
  Аналогично `replaceState`, плюс слушать `popstate`.
- Дополнительно: `MutationObserver` на контейнер плеера — ловит смену трека без
  навигации URL.
- При смене «экрана» сайта (например, из плеера в поиск) оверлей либо скрывается,
  либо остаётся, но не показывает чужой текст. Правило: показываем только когда
  есть `trackId` и `duration`.

## Preact-нюансы

- `render(vnode, shadowRoot)` работает, но TypeScript не считает `ShadowRoot`
  элементом — нужен явный каст или типизированная обёртка.
- Не использовать глобальные стили из `document` — они не попадут внутрь.
- CSS лучше держать строкой в TS-модуле (Vite умеет `?inline`) и подключать в
  shadow root через `<style>`; так не нужен отдельный файл на диске у пользователя.
- Никаких компонентов, которые монтируют свои стили в `document.head` (некоторые
  UI-киты так делают) — внутрь shadow root они не попадут.

## Гигиена расширения

- Соблюдать CSP страницы: не вставлять внешние скрипты.
- Не подключать сторонние icon-шрифты — использовать инлайн SVG.
- UI не должен воровать фокус: горячие клавиши плеера (пробел, стрелки) должны
  работать. Не делать `preventDefault` на клавишах, пока фокус не в нашем
  инпуте.
- Держать DOM оверлея маленьким (десятки строк — не сотни), иначе скролл и
  анимации страницы просядут.

## Как проверять

- Визуально: на Яндекс Музыке, на YouTube, в тёмной и светлой теме сайта.
- Поведение: ресайз окна, скролл, смена трека, перемотка, переход в другой раздел
  сайта, сворачивание плеера.
- `getComputedStyle` скриптом — только для конкретных свойств, не дампить весь
  HTML (см. `projectRules.md` §16.2).

## Красные флаги

- Монтирование в `document.body` без shadow root.
- Стили в `document.head`.
- Фиксированная позиция без пересчёта на ресайз.
- `pointer-events: auto` на весь оверлей — блокирует кнопки сайта.
- Размонтирование оверлея при смене трека.
